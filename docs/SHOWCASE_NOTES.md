# SceneLoop Showcase · 证据与展示边界

本文件说明公开仓库的展示材料如何对应真实项目进展。它不是额外的运行报告，也不替代现场可复现测试。

## 1. 产品实现与定位

SceneLoop 将通用模型接入专业三维创作工作流，内建 Director（规划）、Builder（施工）、独立 Judge（评审），并通过 Blender 场景执行、渲染观察、几何检查、Working/Candidate/Checkpoint 及操作回执连接整条链路。

**与通用编程 Agent 的差异是产品化的三维任务协议，而不是宣称其他 Agent 无法操作 Blender、无法多轮工作。** 不同模型在同一场景协议下可以复用创作方法和证据组织。

## 2. 一次已记录的真实施工案例

提供给作品集的 Test1 / Showcase-R3 运行摘录记录：

| 事实 | 记录值 |
| --- | --- |
| 模型请求 | 16 次 Builder/Brain 调用；另有 2 次 Judge 调用 |
| Builder 工具调用 | 23 次 |
| 草稿编辑 | 3 次 |
| 正式保存 | 1 次，Working Version 4（r003） |
| 独立 Judge | `continue`，逐项 3/7 判为通过 |

该案例的亮点不只是生成画面，而是 **Judge 能够确认已改善的部分，同时针对屋面、守护兽、地形接缝和道具细节继续提出具体修改意见**。这里的 `continue` 不是整体质量 PASS，不应改写为全部验收通过。

这些数据源于参赛证据包中的真实 Run 摘录与图像素材；公开代码仓库本身**未包含该 Run 的 SQLite、原始模型请求和全部运行文件**，因此本文件不是对该运行的独立复现声明。

## 3. 材质与精修：同源但不同执行环境

Test4 的场景后续材质与局部精修实验沿用了原始场景文件，分开展示木材、石材、地表以及材料分层、通道关联等方法。

这些彩色场景和桌面使用痕迹特写，**是同源场景经外部 Blender/Agent Harness 后续实验的成果**，不能宣称它们全部来自目前公开的 SceneLoop 原生 Builder 流程。

沉淀的方法库： [realistic-materials-skill](https://github.com/RobotQv/realistic-materials-skill)。

## 4. 当前状态

这份公开仓库是 **Showcase 原型源码**，包含 Windows 本地工作台与运行代码，但不包含模型权重、API Key、历史场景数据或参赛展示视频。

原型已获得真实施工、场景保存和独立评审证据，长流程中的权限与恢复接线仍可能出现阻断。**请不要将本仓库视为零配置、任意场景均可一次跑通的稳定发行版。**

仓库内两张 SVG 为解释设计而制作的原创概念插画，不是 Blender 运行截屏。
